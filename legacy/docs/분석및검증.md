# 결보강 도우미 분석 및 검증

기준일: 2026.10.29.

## 1. 검토 자료와 기존 구조

| 자료 | 확인 범위 |
|---|---|
| `class_swap(1).html` | 전체 1,423행의 생성기·후보 계산·계획서·인쇄 로직 |
| `2026학년도 2학기 전체 교사 시간표(최종)(2).xlsx` | `전체 교사 시간표` 시트의 머리글·교사별 과목/교실 행 |
| `선택과목정보(2학기)(2).xlsx` | `선택과목정보_템플릿` 시트의 자료 198행 |

기존 HTML은 전체 시간표와 선택과목 파일을 읽어 `cs_tt.html`과 `index.html`을 생성하는 도구입니다. 생성된 시간표 파일에 자료를 Base64로 포함하고, 두 화면 사이에 `localStorage`로 선택 결과를 전달합니다. 작성 내용의 기기 간 공유와 서버 저장 기능은 없습니다.

새 도구는 기존의 단일 수업 교체·보강·계획서·학급 공지 기능을 웹 화면 하나에 통합하고, 인증된 사용자가 서버에 저장하도록 개편했습니다. GitHub·Apps Script·비공개 스프레드시트를 사용하며 새로운 DB나 별도 유료 서버를 추가하지 않았습니다.

## 3. 제거·축소한 자료

| 대상 | 처리와 근거 |
|---|---|
| 시간표의 빈 셀과 장소 없는 `공강` | 저장하지 않고 조회 시 미배정으로 계산 |
| 시간표의 중복 교사명·번호·집계 시수·담임·비고 | 후보 계산과 계획서 출력에 사용하지 않아 저장 대상에서 제외 |
| 엑셀의 셀 서식·인쇄 설정·병합 정보 | 가져오기 후 보관하지 않음. 원본의 머리글 배치를 해석하는 데만 사용 |
| 선택과목의 반복 행 | 학년·과목명·축약명 기준으로 중복 제거 |
| 선택과목의 선택반명·수업교실 | 현재 기능은 선택과목 단일 수업 교체를 제한하므로 저장하지 않음 |
| 선택과목 목록의 `공강` | 과목 규칙에서 제외하고 시간표의 공강 배정 여부로 별도 처리 |
| HTML 재생성·폴더 선택·두 화면 이동 | 하나의 웹 화면으로 통합 |
| 자료 Base64 포함·화면 간 임시 전달 키 | 교사 자료는 서버에서 조회하며, 실제 교사 자료를 공개 HTML에 포함하지 않음 |
| 별도 글꼴 파일 폴더·초기 로딩 시 엑셀 라이브러리 | 글꼴은 HTML 내장, 엑셀 읽기는 관리자 파일 분석 시에만 사용 |

연속수업 연결 정보와 공강의 학급·장소는 후보 계산에 영향을 주므로 유지했습니다. 향후 선택과목 여러 분반을 한꺼번에 옮기는 기능을 추가할 때는 선택반·교실·동시수업 조건을 별도로 설계해야 합니다.

저장 셀 수는 약 47.2% 감소합니다. 다만 새 형식은 안정적인 교사 식별자·연속수업·학년별 과목 규칙·출처 정보를 포함하므로, 비교용 비압축 JSON은 기존 101,625바이트에서 새 형식 100,726바이트로 약 0.9% 감소합니다. 셀 수 감소를 그대로 전송 용량 또는 실행 속도의 감소율로 볼 수는 없습니다. 엑셀 원본은 압축 파일이므로 이 수치와 직접 비교하지 않았습니다.

## 4. 발견된 계산상 문제와 반영 결과

| 기존 동작 | 새 동작 |
|---|---|
| 과목에 `공강`이 포함되면 모두 빈 시간으로 판정 | 식별 기호나 학급·장소가 있는 공강은 배정 시간으로 취급 |
| 창체 보강 시 전체 교사를 후보로 제공 | 같은 실제 날짜·교시에 빈 시간이 있는 교사만 후보로 제공 |
| 선택과목을 단순 부분 문자열로 판정 | 학년과 과목/축약명 뒤의 선택반 기호 경계를 확인. `미적분`과 `미적분Ⅰ` 구분 |
| 수요일 7교시도 표에 생성 | 엑셀 머리글에서 확인된 실제 교시만 운영 |
| 브라우저별 계획을 서로 알 수 없음 | 저장한 계획의 교사·날짜·교시를 다른 사용자 후보 계산에 반영 |
| 저장 직전 다른 사용자의 변경을 확인하지 않음 | 서버에서 후보 조건과 계획서 수정 버전을 재검사 |
| 서로 다른 주간의 날짜 조건을 단순 요일로 판단 | 교체 양쪽의 실제 날짜·교시 사용 |
| 기록 도중 입력값이 바뀔 수 있음 | 초기 로딩·조회·저장 중 입력 제어 |

일반 교체는 같은 학급·대상의 두 수업에 대해 결강 시각의 대상 교사, 교체 시각의 결강 교사가 각각 미배정인지 확인합니다. 선택과목·창체·연속수업·확인 대상 수업은 단일 교체에서 제외합니다. 보강은 같은 시각의 공강 여부를 확인합니다.

저장된 교체는 두 교사의 두 시각을 모두 예약하여 같은 원래 수업을 다른 교체에 중복 사용하지 않도록 했습니다. 이는 이동으로 생긴 빈 시간을 연쇄 교체에 다시 사용하는 기능까지 허용하는 계산 방식은 아닙니다. 계획서를 취소하면 예약은 해제되고 이력은 남습니다.

## 5. 원본에서 확인이 필요한 사항

1. **학년도:** 파일명은 2026학년도이나 시간표 내부 A2는 `2025 학년도`입니다. 어느 표기가 맞는지 확인이 필요합니다. 새 도구는 이 불일치를 관리자에게 표시합니다.
2. **축약명:** 시간표의 `중문I`와 선택과목 정보의 `중문화`가 일치하지 않습니다. 해당 2시간은 축약명 확인 대상으로 분류하여 단일 교체를 제한했습니다. 과목의 정식 명칭을 임의로 단정하지 않았습니다.
3. **공강 배정:** 학급이나 장소가 기입된 공강의 실제 업무 성격은 원본만으로 확정할 수 없습니다. 미배정으로 오인하지 않도록 보호했으며, 필요하면 관리자가 해당 셀을 정정할 수 있습니다.
4. **개인 복무 일정:** 출장·연가·회의·학교 행사·특별실 사용 가능 여부는 첨부 자료에 없습니다. 시간표상 후보와 실제 협의 가능 여부를 함께 확인하여 사용해야 합니다.

## 6. 구현 범위

- 교사·관리자 비밀번호 로그인. 비밀번호 비교와 세션 검사는 서버에서 수행.
- 관리자 화면에만 자료 업로드·셀 수정·선택과목 수정·비밀번호 변경·내보내기·복원 제공.
- 교체·보강 후보 조회와 교사 시간표 두 개 대조.
- 계획서 1–24건 작성, 수업별 수정·삭제·순서 변경, 서버 저장·수정·취소.
- 저장 이력 검색과 계획서·학급 공지 인쇄.
- 데이터 변경 시 수정 버전 확인, 저장 재시도 시 최초 요청의 중복 생성 방지.
- 시간표 자료 캐시와 자료 변경 여부에 따른 중복 전송 생략.
- PC에서는 시간표 두 개를 나란히 배치하고, 좁은 화면에서는 세로로 배치.

비밀번호는 역할별 공용 방식입니다. 교사별 개별 계정·작성자별 수정 제한·전자결재 연동은 구현 범위에 포함하지 않았습니다. 기존 교사들이 공동으로 계획서를 관리하는 용도입니다.

서버 저장 시트는 자료와 계획서 두 종류입니다. 시간표 저장 영역 A/B는 기록을 완료한 자료만 현재 자료로 바꾸기 위한 복구 구조이며, 불필요한 누적 사본을 생성하는 기능이 아닙니다. 완료된 과거 계획서는 당시 수업 정보를 보존하며 다음 학기 시간표 등록을 막지 않습니다.

## 8. 구현 근거

- Google Apps Script의 [HTML 클라이언트·서버 통신](https://developers.google.com/apps-script/guides/html/communication): 비동기 `google.script.run`과 비공개 함수 규칙.
- Google Apps Script의 [Cache](https://developers.google.com/apps-script/reference/cache/cache): 키별 캐시 크기를 고려해 자료를 나누어 캐시하며, 원본 저장소를 별도로 유지.
- Google Apps Script의 [XFrameOptionsMode](https://developers.google.com/apps-script/reference/html/x-frame-options-mode): GitHub 연결용 화면에 임베딩 모드 적용. 실제 연결 확인 필요.
- SheetJS의 [공식 브라우저 배포 안내](https://docs.sheetjs.com/docs/getting-started/installation/standalone/): 관리자 엑셀 분석 시 공식 0.20.3 배포본 사용.

최종 산출물은 설치 파일과 초기 입력용 자료입니다. 현재 계정의 실제 Google Apps Script 배포나 기존 개인시간표 데이터 변경은 수행하지 않았습니다.
