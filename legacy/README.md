# 수업 결·보강 도우미 설치·사용 안내

제작일: 2026.10.29.

GitHub Pages에서 화면을 제공하고, Google Apps Script에서 인증·계산·저장을 처리하며, 비공개 Google 스프레드시트에 자료를 보관합니다. 기존 개인시간표와 같은 운영 방식입니다. 이 패키지는 설치용 완성본이며 실제 Google 저장소 연결·배포는 아직 수행하지 않았습니다.

## 1. 파일별 설치 위치

| 폴더·파일 | 설치 위치·용도 |
|---|---|
| `github/index.html` | 결보강 도구용 GitHub 저장소의 루트 |
| `github/config.js` | 같은 저장소 루트. 새 Apps Script 웹앱 주소 입력 |
| `apps-script/Code.gs` | 새 스프레드시트의 Apps Script |
| `apps-script/Core.gs` | 같은 Apps Script. 공통 계산 규칙 |
| `apps-script/App.html` | 같은 Apps Script의 HTML 파일 `App` |
| `apps-script/Bridge.html` | 같은 Apps Script의 HTML 파일 `Bridge` |
| `apps-script/appsscript.json` | 같은 Apps Script의 매니페스트 |
| `private-data/initial-data.json` | 관리자 화면에서 한 번 업로드할 초기 자료 |
| `docs/분석및검증.md` | 자료 분석·변경 사항·검증 범위 |
| `tests/` | 개발 검증용. 웹에 업로드할 필요 없음 |

**기존 개인시간표의 Apps Script와 분리하여 새 스프레드시트에 설치합니다.** GitHub 저장소에는 `github` 폴더 안의 두 파일만 올립니다. 초기 자료·엑셀·전체 ZIP은 관리자 화면의 업로드 자료입니다.

## 2. Google 저장소 설치

1. 새 Google 스프레드시트를 만듭니다. 스프레드시트는 비공개 상태로 유지합니다.
2. `확장 프로그램 → Apps Script`를 엽니다.
3. 기본 코드 파일에 `Code.gs` 내용을 넣고, 스크립트 파일 `Core`를 추가해 `Core.gs` 내용을 넣습니다.
4. HTML 파일 `App`, `Bridge`를 각각 만들어 해당 파일의 내용을 넣습니다. 이름의 대소문자를 맞춥니다.
5. `프로젝트 설정 → 편집기에 appsscript.json 매니페스트 파일 표시`를 켜고 동봉한 매니페스트 내용을 적용합니다.
6. 저장 후 편집기에서 `setupClassSwap`을 한 번 실행하고 소유자 계정으로 권한을 승인합니다.
7. `배포 → 새 배포 → 웹 앱`을 선택합니다. 실행 사용자는 `나`, 액세스 권한은 `모든 사용자`로 설정합니다.
8. 배포된 `/exec` 주소를 복사합니다.

초기 설정은 저장용 시트 `결보강_자료`, `결보강_계획서` 두 개를 생성합니다. 기본 빈 시트는 직접 정리해도 됩니다. 저장 시트의 내용을 수작업으로 편집하는 대신 웹 관리자 화면을 사용합니다.

비밀번호·세션 정보는 스프레드시트 셀과 공개 화면 파일에 저장하지 않습니다. 초기 교사·관리자 비밀번호는 각각 `1234`이며 관리자 화면에서 별도로 변경할 수 있습니다.

## 3. 초기 자료 등록

1. 배포된 Apps Script 웹앱 주소를 엽니다.
2. 화면 오른쪽 아래 `관리자`를 눌러 관리자 비밀번호로 로그인합니다.
3. `자료 관리 → 초기 자료·내보낸 자료`에서 `private-data/initial-data.json`을 선택합니다.
4. `파일 분석`으로 교사 64명, 배정 1,149시간, 선택과목 규칙 54개, 주간 운영 34교시를 확인합니다.
5. `등록`을 눌러 저장합니다.
6. 교사·관리자 비밀번호를 변경합니다.

초기 파일에는 첨부 시간표에서 추출한 실제 교사 정보가 들어 있습니다. 시간표 내부에는 `2025 학년도`, 파일명에는 `2026학년도`가 표시되어 있어 경고를 유지했습니다. 어느 학년도 표기가 맞는지 확인이 필요합니다. 초기 시간표 이름은 파일명의 `2026학년도 2학기`를 사용했습니다.

## 4. GitHub 화면 연결

1. `github/config.js`의 `apiUrl`에 새 웹앱의 `/exec` 주소를 넣습니다.

```javascript
window.CLASS_SWAP_CONFIG = Object.freeze({
  apiUrl: '여기에 새 결보강 웹앱의 /exec 주소 입력'
});
```

2. `github/index.html`, `github/config.js`를 결보강 도구용 GitHub 저장소 루트에 올립니다.
3. `Settings → Pages`에서 사용할 브랜치와 `/(root)`를 설정합니다.
4. 발급된 GitHub Pages 주소를 열어 로그인과 자료 조회를 확인합니다.
5. 관리자 `자료 관리 → 사이트 주소`에 사이트의 출처를 저장합니다. 예시는 `https://계정명.github.io`이며 저장소 경로는 입력하지 않습니다. 별도 도메인을 사용할 때는 해당 도메인의 출처를 입력합니다.

GitHub 화면과 Apps Script 사이의 통신은 숨겨진 연결 화면을 통해 처리합니다. 브라우저의 교차 출처 요청을 우회하는 `no-cors` 저장이나 JSONP 저장은 사용하지 않습니다. GitHub 연결이 제한되는 환경에서는 Apps Script `/exec` 주소로 직접 같은 도구를 사용할 수 있습니다.

## 5. 교사 사용 순서

1. 교사 비밀번호로 로그인합니다.
2. 결강 교사, 사유, 작성일, 제출자를 입력합니다.
3. `수업 교체` 또는 `보강`을 고르고 결강 주간의 수업을 누릅니다.
4. 대상 교사를 선택합니다. 교체라면 오른쪽 시간표에서 교체 수업도 선택합니다.
5. `계획에 추가`를 누릅니다. 여러 수업을 추가하거나 수정·삭제·순서 변경할 수 있습니다.
6. `계획서 저장`을 누릅니다. 저장 전 내역은 다른 사용자에게 반영되지 않습니다.
7. `저장된 계획서`에서 열기·인쇄·학급 공지·취소를 처리합니다.

계획서 한 건에는 수업 1–24건을 넣을 수 있습니다. 계획서는 8건씩 나누어 A4 세로로, 학급 공지는 수업별 A4 가로로 출력하도록 구성했습니다. 학교의 기존 교사 간 협의·결재 절차에 따라 사용합니다.

후보는 업로드된 기본 시간표와 저장된 계획서를 기준으로 산출합니다. 별도 출장·연가·회의·특별실 사용 일정은 확인 가능한 자료에 포함되어 있지 않습니다. 날짜·요일은 일치 여부를 검사하며 수요일 7교시처럼 운영되지 않는 교시는 선택할 수 없습니다.

교사 로그인은 공용 비밀번호 방식입니다. 교사별 개인 계정이나 계획서별 소유자 권한을 구분하지 않으며, 로그인한 교사끼리 저장된 계획서를 공동 관리합니다.

## 6. 관리자 자료 갱신

- 새 학기에는 전체 교사 시간표와 선택과목 엑셀을 함께 선택해 `파일 분석 → 등록`합니다. 원본 파일의 서식·도형·수식·빈 셀은 저장하지 않습니다.
- 선택과목 파일의 양식은 `학년, 선택반명, 교과명, 수업교실, 축약과목명` 머리글을 기준으로 읽으며, 계산에 필요한 학년·과목명·축약명만 저장합니다.
- `교사 시간표 수정`에서 교사를 선택한 뒤 셀을 눌러 과목·학급을 고칠 수 있습니다. 연결 표시로 이어진 수업은 해당 묶음을 함께 수정합니다.
- `선택과목 → 목록 수정`에서 한 줄에 `학년,과목명,축약명`을 입력합니다.
- 아직 진행되지 않은 저장 계획과 새 시간표가 충돌하면 변경을 중단합니다. 과거 계획서는 저장 당시의 수업 정보를 유지하므로 다음 학기 시간표 등록을 막지 않습니다.
- `중문I`는 선택과목 파일의 `중문화`와 표기가 달라 확인 대상으로 분류했습니다. 원본 시간표 또는 선택과목 규칙의 축약명을 맞추면 분류가 갱신됩니다.
- `공강B`, `공강D1`과 학급·장소가 지정된 `공강`은 별도 배정이 있는 시간으로 처리합니다. 실제 빈 시간으로 사용할 경우 관리자 화면에서 과목·교실을 모두 비웁니다.

Apps Script 파일을 수정한 뒤에는 `배포 관리 → 기존 배포 수정 → 새 버전`으로 배포합니다. 기존 배포를 갱신하면 `/exec` 주소를 유지할 수 있습니다. GitHub 화면을 수정할 때는 `index.html`을 교체합니다.

## 7. 자료 보존·복원

관리자의 `자료 내보내기`는 시간표·선택과목·계획서·취소 이력을 JSON으로 내려받습니다. 이 JSON을 `초기 자료·내보낸 자료 → 파일 분석 → 전체 복원`으로 업로드하면 복원할 수 있습니다. 복원은 현재 자료 전체를 교체하므로 화면에서 확인 후 진행합니다.

원본 시간표 자료는 스프레드시트의 두 저장 영역을 번갈아 사용하여 기록이 완료된 영역만 현재 자료로 전환합니다. 직전 자료 영역 한 개는 기록 도중 오류가 발생한 경우를 위한 복구용입니다. 별도의 백업 문서나 누적 사본을 계속 생성하지 않습니다.

서버 응답이 늦어진 경우 작성 내용을 유지합니다. 새로고침으로 실제 저장 여부를 확인한 뒤 같은 계획서를 다시 저장할 수 있으며, 최초 저장 재시도에는 같은 식별자를 사용하여 중복 생성을 방지합니다. 수정 버전이 다른 사용자의 저장과 겹치면 덮어쓰기를 차단합니다.

## 8. 검증 범위

계산 규칙 21건, Apps Script 환경 모의 테스트 18건을 통과했습니다. 첨부 자료로 실제 교체 6건·보강 49건의 후보를 계산하여 유효성을 확인했습니다. 브라우저에서는 후보 선택, 계획 추가·저장·이력 조회와 PC·390px 모바일 레이아웃, 인쇄 영역을 점검했습니다.

실제 Google 계정의 배포·권한·저장 응답, GitHub Pages와 실서버 연결, 실제 프린터의 여백·축소 배율은 아직 검증하지 않았습니다. 설치 후 계획서 한 건을 저장하고 다른 브라우저에서 조회하는 최종 연결 확인이 필요합니다.

개발 재검증 명령:

```text
python3 build.py
node tests/core.test.cjs
node tests/server.test.cjs
```

프리텐다드를 기반으로 필요한 글자를 포함한 글꼴을 HTML에 내장했습니다. 수정 글꼴의 이름은 라이선스에 따라 `Schedule Sans`로 변경했으며 원저작권·OFL 전문을 HTML과 `docs/LICENSE-Pretendard.txt`에 포함했습니다. 별도 글꼴 폴더를 설치할 필요는 없습니다. 엑셀 읽기 라이브러리는 관리자 파일 분석 시에만 불러옵니다.
